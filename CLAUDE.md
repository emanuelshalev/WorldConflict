# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

World Conflict, a turn-based geopolitical simulation game set in Nov 2026 (41 countries; also 1960, 1990 and Jan 2025 eras). Fastify + TypeScript backend at the repo root (`src/`), React 19 + Vite frontend in `ui/` (separate package.json, separate `npm install`). SQLite via Prisma for save games. Three modes: Flashpoint (12 turns, authored objective), Term (48, election/review finale), Legacy (120). LLMs are optional and tiered (ALGORITHMIC / KEY_DECISIONS / FULL_LLM), `src/agents/fallback.ts` PersonalityAI drives every country by default. Requires Node ≥ 20.19.

## Commands

```bash
npm run setup        # first-time setup: both installs, .env, SQLite or JSON-file saves (setup.cmd / setup.sh)
npx prisma db push   # (manual alternative) create/update dev.db (DATABASE_URL defaults to file:./dev.db)

npm run dev          # backend (tsx watch, port 8080) + frontend (Vite, port 5173) concurrently
npm run dev:api      # backend only
npm run dev:ui       # frontend only

npm run test                                    # all tests (vitest); timing tests in tests/perf run after the main suite
npx vitest run tests/core/turn.spec.ts          # single test file
npx vitest run -t "determinism"                 # tests matching name
npm run perf                                    # perf tests in tests/perf
npm run sim -- --mode TERM --scenario 2026 --countries USA,UKR --games 12 --policy smart,none
                                                # headless playtest harness (balance metrics)
npm run bench:reveal                            # regenerate data/benchmarks/ (~15 min), commit it
npm run playtest:smoke                          # UI smoke playtest (needs npm run dev)

npm run lint         # biome: backend src/ only
npm run lint:fix     # biome with auto-fix
cd ui && npm run lint  # eslint for the frontend (separate toolchain)

npm run build        # tsc (backend → dist/) + vite build (frontend)

npm run verify                    # merge gate: tests, lints, build, balance bands, own servers, smoke, reveal, visual, finding guards
npm run verify -- --quick         # tests, lints, build and the regression registry check only
npm run verify -- --full          # adds the orders / world map acceptance scripts
npm run verify -- --changed       # suites and finding guards covering files changed since the branch base
npm run verify -- --update-visual # rewrite tests/visual/__screenshots__ after an intended UI change
```

Backend env vars go in `.env` at the root (loaded via dotenv): `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` / `GEMINI_API_KEY_PERSONAL`, `LLM_PROVIDER`, `PORT`, `DATABASE_URL`, `CORS_ORIGINS`. Players normally bring their own LLM key via the in-game Settings.

## Architecture

### Determinism is a core invariant

The simulation engine (`src/core/`) must be fully deterministic: same seed + same actions → identical world state. All randomness goes through `SeededRandom` from `src/core/seed.ts`; per-turn seeds are derived via `combineSeed(worldSeed, turn)`. Never use `Math.random()` or wall-clock time inside `src/core/`. `tests/core/determinism.spec.ts` enforces this over 24-turn simulations, run it after any change to turn resolution.

### Layering

- `src/core/`: pure simulation engine, no I/O, no LLM calls. `TurnEngine.executeTurn(state, playerActions, aiIntents, decisionChoices)` clones the state (`structuredClone`) and runs phases: resolve crisis decisions (effects, injected actions, follow-ups) → world events (`events.ts`, AI-world only) + the drama director (`crises.ts`: ~30 player crisis templates, shocks, follow-ups, per-mode cadence, cooldowns) → belief updates → action resolution (player orders cost political capital / budget share, `costs.ts`) → wars → nuclear → economy/domestic/diplomatic drift/tension → government dynamics (elections; coups and revolutions are telegraphed to the player as crises first) → scoring + player turn report → newspaper (player-led headline) → game over (`objectives.ts`: conditions, early failure, stars). Domain subsystems live in `src/core/systems/` (`hotspots.ts`: Gaza and the West Bank as hot zones that are not states, seeded per scenario, moved by `hot:<ID>:<metric>` crisis effects). `preview.ts` predicts action consequences without mutating state. `outcomes.ts` turns each player order into a dispatch (before/after facts, varied deterministic narration, failure stories) and keeps `director.ledger`, the headline number of each order type after every use. `orders.ts` is the player's order list as data; `availability.ts` decides whether an order can be given (rule layer: `OrderBlock {code, reason, fix, points, alt?}`; the UI adds the month layer in `ui/src/lib/availability.ts` with identical copy, and preview, `/orders/menu` and Execute share it). `chronicle.ts` `recordMonth` samples each month for the reveal; `reveal.ts` (+ `reveal-text.ts`, `achievements.ts`: 37 seals + one signature per flashpoint side) builds the end-of-session payload (Presidency Score 0-1000, achievements with benchmark rarity, moments, perception, declassified truth, flashpoint `reality` table, ranking, seed codes `HC-USA-3AF` / `T2026-USA-...`). `era.ts` is the era filter (countries `PART_OF` / `NOT_INDEPENDENT` in the scenario get no AI orders, pacts, events, crisis roles and cannot be targeted as states; they are led only with `whatIf`, and the player's own country is never marked); `opening.ts` builds the One Term "Start with" opening crisis from an era situation; `replay.ts` rebuilds a save at any month from `world.origin` + `world.inputs` (recorded by `/turn`); `era-map.ts` builds the title globe's era map (display only). `codex.ts` holds codex/situation schemas and date/era filters (no I/O, never in `WorldState`). `meetings.ts` builds the monthly calendar. `missionImpact.ts` says which objectives an option or order helps, hurts or breaks; `advisors.ts` (suggestions, cabinet pick vs mission pick, meeting picks, staff orders with variety rules) feeds the `advice`/`missionImpact`/`objectiveStatus` payload and the harness `staff`/`staffswitch` policies; `scoring.ts` `scoreBreakdown` names the terms behind each score part; `explain.ts` fills the report's drift, follow-ups, step objective and repeat marks; `reactions.ts` `freshLines` keeps reaction lines from repeating (`director.recentLines`).
- `src/core/types.ts`: single source of truth for domain types, all defined as Zod schemas. `CountryProfileSchema` validates the static JSON files in `data/countries/`; `CountryStateSchema`/`WorldStateSchema` are the runtime state. Scenario era-overrides (`leaders`, `countryOverrides`) are validated by `ScenarioSchema` in `data-loader.ts`.
- **Asymmetric information is real**: each country holds `beliefs` (noisy estimates of others' strength/GDP/stability/nuclear progress, accuracy driven by intel vs counter-intel). The AI decides from beliefs, not ground truth, and the API returns a belief-filtered `playerView` (with uncertainty ranges) for foreign countries.
- `src/agents/fallback.ts`: `PersonalityAI`, the deterministic country AI: decisions weighted by personality traits, historical rivals/allies, red lines, leader style, regime constraints and beliefs. `strategist.ts` `planTurn(world, aiConfig)` is what `POST /api/turn` uses: it returns PersonalityAI intents, replacing selected countries' intents with validated LLM proposals per tier (fallback on any failure/timeout/budget cap). `usage.ts` meters tokens/cost (persisted per save in `SaveGame.llmUsage`). Providers: `llmClient.ts` (OpenAI, Gemini, Ollama, OpenAI-compatible `local`) and `providers/anthropic.ts` (official SDK).
- `src/api/`: Fastify routes. `routes/game.ts` is stateless (loads from DB per request): `/new-game` (mode, difficulty, flashpointId, daily, seed, seedCode, whatIf, opening), `POST /branch` (saveId, month: a new save rebuilt from origin + inputs, `core/replay.ts`), `/turn` (`playerActions`, `decisions`, optional `ai` tier config), `/preview-action`, `/orders/menu` (every order for one target with cost, chance, block), `/report/:saveId`, `/reveal/:saveId` (409 while running), `POST`/`GET /runs` (run history, `RunResult` or `saves/runs.json`), `/scenarios` (+ flashpoints + daily), `/scenarios/:id/map` (era map), `/countries`, `/saves` (`?playerId=&guestId=`, both owners together), `/load/:saveId`, `DELETE /save/:saveId`. `routes/codex.ts`: `GET /codex?scenario=&flashpoint=` (ETag; outside production it re-stamps `data/codex`, `scenarios`, `flashpoints` per request and drops caches when a file changed, so a running dev server serves fresh codex). Payloads pass through `publicWorldState()` (also strips the chronicle's `start`/`plots`) so foreign ground truth never reaches the client; the reveal is the only post-game exception (`declassified`). Every payload carries `monthAdvice()` (`advice`, `missionImpact`, `orderImpact`, `objectiveStatus`) and `pcIncome`/`pcCap`.
- `src/infra/db.ts`: two save stores behind `gameDb`: SQLite via Prisma + better-sqlite3 (optional dependencies, loaded lazily; `DATABASE_URL`, default `file:./dev.db`) and `JsonStore` (one JSON file per save in `saves/`), used when `DB_DRIVER=json` or when SQLite fails to load. World state is re-validated with `WorldStateSchema` on write and on load. `npm run setup` (`scripts/setup.mjs`, wrappers `setup.cmd` / `setup.sh`) installs and picks the store.

### Frontend

`ui/src/store/gameStore.ts` (Zustand) holds the server payload (`worldState`, belief-filtered `playerView`, `pendingDecisions`, `objectiveStatus`, `score`, `gameOver`), screen (`title | game`), pending orders (with server previews), crisis choices, AI-tier settings (localStorage) and usage, guest id (saves without an account). **Types are duplicated, not shared**: `gameStore.ts` re-declares the backend types, changing a backend schema means updating both. Scenes: `ui/src/scenes/` stages every order, crisis and story as one of 20 animated SVG broadcast scenes (`kinds.ts` maps action types, crisis templates and headlines to scenes; art in `scenes/art/`, contract in `art/STYLE.md`). After Execute (`Chronicle.tsx`): optional `BigMoment` (`lib/moments.ts`, at most one a month) → `scenes/ResultCard.tsx` → optional details (`MonthDebrief`, pages of `OutcomeCard`s grouped by `lib/debrief.ts`; reactions and facts come from the engine) → the paper, per the "After each month" setting. `#scenes`, `#clip`, `#mapfx`, `#moments` are dev gallery routes. Orders: one `components/orders/OrderCard` on desk (`OrderCatalog`), map menu (`MapActionMenu`) and dossier (`CountryDetailPanel`), with `ConfirmFace` (declare war, nuclear strike, mission warnings), `CountryPicker`, and `lib/pointAt.ts` lighting the `[data-point]` element a reason is about; all queue through `queueOrder()`. Player-facing words come from `lib/glossary.ts` (`tests/ui-glossary.spec.ts` bans synonyms in UI strings, objective labels and docs/GAMEPLAY.md). Month: `desk/YourMove`, `desk/GoalLine` (under the HUD, opens the Mission sheet; month 1 adds `MissionLine`, the goal in one sentence above the crisis, from `lib/goals.ts` `missionSentence`), `desk/AdvisorList` (desk, full desk and map strip, each suggestion is the shared `OrderCard` row; why lines, Big move from `lib/ease.ts`), `desk/Coach`; staff propose up to 2 orders (`lib/month.ts`): a `PendingAction` with `proposed: true` holds no political capital, order slot or defense money until approved (`approveProposal()`, Approve all), and Execute sends only `committedActions()`; the harness `staff` policy is Approve all. Every Approve all control lives inside `desk/StaffPicks` (RS-005: rail, phone plan sheet, map strip): the titled "Staff picks" list from `lib/month.ts` `staffPickItems()` (crisis cabinet picks, proposals, meetings, deputies, each with Approve and Change) and the main button "Approve n staff picks" whose count is that list; folded in Map mode it only unfolds the list. The map menu closes when the desk takes over (`lib/ease.ts` `mapMenuShown`). Sound: WebAudio synth in `lib/sound.ts`. Reveal: `EndScreen` → `reveal/RevealSequence` (8 stages in `reveal/model.ts`), share cards in `lib/shareCard.ts`, local run history in `lib/runs.ts`. Learning aids: `components/learn/*` (Explainer, SituationBriefing, BriefingPanel, Codex drawer, FamiliarityPrompt), levels Guide me / Some help / I know this (`lib/codexMatch.ts` `LEVEL_RULES`; Guide me also shortens the crisis text before More, `lib/month.ts` `guideLede`), progress in `localStorage` (`lib/learn.ts`). The situation briefing never opens by itself unless the Settings toggle is on (`autoBriefOn`, off by default at every level). Screens: `TitleScreen` (the globe is the menu: `TitleGlobe` pins every flashpoint, or in Term/Legacy shows the era's world from `/scenarios/:id/map` with time travel between eras, `globe/` layers and `EraCard`; a dossier picks the side, era and nation; `reveal/YourRecord` and Play this seed), `Hud` (with the Map/Desk switch and ticker toggle), `Desk` (Desk mode: `desk/Navigator`, `desk/Detail`, `desk/CommandRail` with budgets, selection, readiness, Approve all and Execute; `CommandStrip` in Map mode; staff defaults in `lib/month.ts` and `lib/staff.ts`, budgets in `lib/budget.ts`, the 2D subject map in `scenes/ContextMap.tsx`), `Chronicle` (post-turn newspaper + "your month"), `EndScreen` (grade, stars, emoji grid, share card), `Drawers` (cabinet/world/chronicle/mission), `SettingsModal` (AI tiers, cost). The map (`MapView.tsx`) draws Natural Earth polygons (`ui/public/world.geojson`, `ADM0_A3`) on a tileless ocean with a colorblind-safe Relations default layer. Design tokens live in `ui/src/styles/wc.css`.

### Game data

Static data is JSON in `data/`: 41 country profiles in `data/countries/` (validated by `CountryProfileSchema`; Natural Earth codes, West Bank = `PSX`), scenarios in `data/scenarios/` (`1960`, `1990`, `2025`, `2026`) with era-accurate leaders, overrides, relations, blocs, starting wars, deployments and briefing lines, and 8 flashpoints in `data/flashpoints/` (`FlashpointSchema`: playable sides, setup, per-side objectives, scripted crises, debrief, per-side `reality` rows and `signature` achievement). Scenarios may carry era map fields (`EraMapFieldsSchema`: `eraStatus`, `blocs`, `situations`, `merged`, `mapFocus`, `mapLabels`, `labelAllow`); the engine reads only `eraStatus` and `blocs`. Leaders keep their real `sinceDate` from the era file. `data/codex/*.json` (~560 entries) + `data/codex/situations/` (one per flashpoint and `scenario-<id>`), schema in `src/core/codex.ts`, checked by `tests/codex/schema.spec.ts`. `data/benchmarks/` is generated (see invariants). `ui/public/era/shapes.geojson` holds vanished borders for the title globe (East Germany, South Yemen). `src/core/data-loader.ts` `newGame()` builds a session (mode, difficulty, flashpoint) and opens with a crisis. Simulated countries are `TIER1_COUNTRIES` in `types.ts`.

### Simulation invariants & balance

- Wars use a single `frontline` (0–100, 50 = stalemate); ends at 85/15 or by exhaustion ceasefire.
- Nuclear: two-strike rule (2 consecutive successful strikes cripple a DEVELOPING program; TESTED+ is invulnerable); nuclear use → global embargo, every relation -60, approval and legitimacy crash, possible retaliation chain → `NUCLEAR_HOLOCAUST` game over; a war won with a nuclear weapon gives no victory rally. An airstrike on a nuclear power (TESTED+) outside a war is an act of war: the target declares war (pacts join), CRITICAL war event, approval/legitimacy/stability fall (`TurnEngine.actOfWar`). `tests/core/wild-moves.spec.ts` guards both.
- One outcome vocabulary: every order, decision and foreign move in the turn report carries `status` (DONE, PARTLY, FAILED, REFUSED, NO_EFFECT) and `reason` from `src/core/status.ts`; a cost is not a failure. `report.yourMove` is the player's own move ("What your choice did"), never a front. The UI renders the status via `ui/src/lib/outcome.ts` and never infers one from facts.
- Global tension has a per-turn rise cap (+8, +30 on war/nuclear shock), AI-generated tension counts half, and it decays 26%/turn toward a war-count floor (min(60, 25+6×wars)). Standing border deployments add at most 1.5/month in total (they used to add 0.5 each and pinned flashpoints near 85). Target: median 45–70, ≤20% of months ≥80, verify with `npm run sim` when adding tension sources.
- Relations drift 2%/month toward a structural equilibrium (alliances, rivalries, regime affinity). Ceasefires depend on exhaustion and who is winning.
- The player can be deposed (election loss, coup, revolution, assassination) but coups/revolutions are telegraphed first (`coup_plot` / `streets_boiling` crises). Sessions end at `world.maxTurns` (mode-dependent). Score is 4×50 components drifting 15%/month toward situation-derived targets.
- Political capital is flat: 2◆/month (3 in FLASHPOINT, +1 on ANALYST), cap 6, no popularity bonus. The player gets at most 6 orders a month (`MAX_ORDERS` in `turn.ts`), one per type+target; only the first denunciation each month moves approval. Crisis-injected actions bypass these limits.
- `CountryState.realGrowth` is the smoothed, annualised *actual* GDP change (computed in `turn.ts` after phase 6). The HUD, the economic score and peacetime voter mood read it; don't show `growthRate` to players.
- AI defence pacts: rare, never with a belligerent, max 4, none with TWN. AI proposals to the player become a `pact_offer` crisis. Wars joined to help someone carry `alliedWith` and end with the principal's war.
- Scripted flashpoint crises can declare `requiresWar: [a, b]` and are skipped once that war is over.
- `DataLoader.newGame()` returns a deep copy: never let game state share objects with the loader's cached profiles/scenarios (it leaked between games in one process).
- Term objectives: survival is the win; bonuses are score 115+ and a statecraft goal (end the inherited war / mend ties with the worst rival). Reform has 6-month diminishing returns outside Flashpoints and lifts `trendGrowth`.
- Generated prose uses `possessive()` / `withArticle()` from `src/core/text.ts` (the UI has a copy of `withArticle` in `ui/src/lib/format.ts`). The order vocabulary and ◆ costs live in `ui/src/lib/actions.ts`.
- Benchmarks: `data/benchmarks/` (score quantiles per seat for smart/random/none, seal rarity) carry a fingerprint of scoring, objectives, costs, chronicle, achievements, reveal, all systems and flashpoint objectives/signatures (`src/infra/benchmarks.ts`). Changing any of these makes `tests/core/benchmarks.spec.ts` fail as stale: run `npm run bench:reveal` and commit the folder. Never hand-merge it; regenerate.
- Era filter: a country with `eraStatus` is not a state (1960: UKR, BLR, SYR, ARE, PSX, NGA until 1960-10; 1990: UKR, BLR; none in 2025/2026, where PSX plays and acts as in v0.9.0); `newGame` refuses it as the player seat outside flashpoints unless `whatIf` (D-56: never remove a seat).
- Replay record: `world.origin` + `world.inputs` (per month: actions, decisions, non-ALGORITHMIC tier). Anything the `/turn` route changes in the world besides `executeTurn` must go through `recordMonth` in `replay.ts`, or branches stop matching their source (`tests/api/seats-replay.spec.ts`).
- Balance targets (harness): smart 70–95% wins pooled (no seat below 65%), none ≤20%, random 15–45%; Iran's Term is exempt. Use `--games 36` near a band edge.

## Conventions

- ESM throughout (`"type": "module"`); backend imports use explicit `.js` extensions (`./types.js`) due to NodeNext resolution.
- Path aliases `@core`, `@agents`, `@api`, `@infra` exist in tsconfig/vitest config, but existing code uses relative imports, match the surrounding file.
- Backend is linted/formatted by Biome (2-space indent, 100-char lines); the UI uses its own ESLint config. Don't run Biome on `ui/`.
- No em dash characters anywhere (docs, site, game text, code, commit messages); use commas, colons, parentheses or a hyphen. `tests/repo-style.spec.ts` enforces it for tracked files and also fails on committed merge-conflict markers (resolve generated files one by one, never with a multi-path checkout).
- `npm test` runs the main suite, then the timing tests in `tests/perf` on their own.
- Commit messages: conventional-commit style (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`).
- Development process lives in `devloop/`, a self-contained, reusable module (method, Playwright kit, templates, `HOW_WE_WORK.md`, `LEARNINGS.md`); World Conflict specifics (customer panel, team charters, goals, gate, decision ledger, journal, iteration runs) are in `devloop/instances/world-conflict/`. Keep product details out of `devloop/method`, `kit` and `templates`. `npm run playtest:smoke` runs the UI smoke playtest (needs `npm run dev`).
- Design docs and project specs live in `dev_plan/` (`spec.md`, `reviews/` expert & persona reviews, `project_status.html` live status page). Public docs: `docs/` (SETUP, GAMEPLAY, ARCHITECTURE, API, DEVELOPMENT).
