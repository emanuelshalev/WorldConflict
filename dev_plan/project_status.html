🌍 World Conflict: Project Status

Road to the public release candidate · latest finished iteration on main (tag iter-3) · work in progress on branch dev/rc1-synthetic-loop (from v0.9.0) · synthetic-customer development loop · live log for the CEO

Mission

Turn World Conflict from a working systems prototype into a game people finish, share and come back to: a geopolitical sim rooted in the real world of November 2026, playable in a 10–15 minute Flashpoint or a multi-day Campaign, beautiful on desktop and mobile, with optional LLM intelligence whose cost is always visible.

Pillars of the overhaul

⏱ Sessions that fit a life

Player picks a mode up front with an honest time estimate: Flashpoint (short, goal-driven, clear win/lose), Campaign (a full term, autosaved across days). Tuned with the headless harness.

🎢 Drama by design

Crisis cadence, escalation curves, near-loss moments and comeback mechanics measured by npm run sim, not left to chance.

🌐 The real world, today

Roster 25 → ~40 countries with current hotspots; a 2026 scenario with active wars; current leaders; flashpoints grounded in real events with "what really happened" debriefs.

🎨 Beautiful & intuitive

Keyless stylized map, situation-room visual identity, progressive onboarding, juicy feedback, shareable end card, mobile layout.

🤖 Three AI tiers

Algorithmic (free, offline) · LLM for key decisions · Full LLM. API key or local model; tokens & estimated cost shown live.

🧪 Expert & player feedback loop

Game-design, UX/visual and geopolitics experts plus four player personas review each milestone; findings feed the backlog.

Who is involved

Three groups: the CEO (real customer number one and owner), the builder team (agents that design, build and test), and the synthetic customer panel (agents that play like real people and are never told what the team hopes to hear). Real signals calibrate the panel.

How we work

We follow the synthetic-customer method (Leveraging Synthetic Customers to Develop Your Product): customer agents are interviewed, use every build through the real UI, and report in a fixed format; the team reacts; every decision is recorded; real feedback corrects the panel. This tab always shows the current process. Each change comes from a journal entry (last tab).

Release gate

    Token consumption

    Where the project's AI work goes, measured from the actual session transcripts (every API response of the orchestrator and every subagent). USD is the real cost: every response priced at its own model's list price per token type (prices map in the registry). Weighted tokens make token types comparable in one number: input-equivalent tokens, each response weighted by its model's own price ratios (cache read 0.05× on Opus and Sonnet 5.5, writes 1.25× or 2×, output 5×). Raw processed tokens are shown too. Generated by devloop/kit/usage-ledger.mjs; attribution rules in devloop/instances/world-conflict/usage/registry.json.

    More ways to slice it

    • By goal and work package (G1 to G12, P1 to P6): tag each agent with the goals it serves to see the cost of each goal. Planned: add goal to the registry rules.
    • Cost per outcome: tokens per verified bug, per accepted change, per point of recommend gained between iterations.
    • Waste: tokens spent on reruns, abandoned agents, environment problems (iteration 0 overload) and harness bugs.
    • Cache efficiency: share of input served from cache, per role; long agent runs with low cache share are candidates for smaller briefs.
    • Model mix: builders on Opus, customers on Sonnet; the share per model shows what moving roles between models would save.
