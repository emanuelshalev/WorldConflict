## Commands

```bash
npm run dev                     # API + UI
npm test                        # all tests; the timing tests in tests/perf run after the main suite
npx vitest run tests/core/drama.spec.ts
npm run lint && (cd ui && npm run lint)
npm run build
npm run sim -- --mode TERM --scenario 2026 --countries USA,UKR --games 12 --policy smart,none
npm run bench:reveal            # regenerate data/benchmarks/ (about 15 minutes)
npm run playtest:smoke          # UI smoke playtest through the real UI (needs npm run dev)
```

Tests worth knowing about:

- `tests/repo-style.spec.ts` fails on any em dash character and on committed merge-conflict markers in tracked files.
- `tests/core/benchmarks.spec.ts` fails when `data/benchmarks/` is stale (see below).
- `tests/ui-glossary.spec.ts` fails on banned synonyms ("PC", "queued", "Orders 2/6"...) in UI strings, objective labels and `docs/GAMEPLAY.md`; `tests/ui-orders-parity.spec.ts` keeps the UI order registry identical to `src/core/orders.ts`; `tests/ui-availability.spec.ts` keeps the UI month-layer copy identical to the engine's.
- `tests/codex/schema.spec.ts` validates every codex file and runs the cross-checks (duplicate ids, dangling references, overlapping aliases, missing sources).

## Invariants

1. **Determinism.** Same seed + same intents ⇒ same world (`tests/core/determinism.spec.ts`). Use `SeededRandom`; never `Math.random()` or wall-clock time in `src/core`.
2. **LLMs propose, the engine decides.** Anything from an LLM is a `CountryIntent` that passes `parseDecision` validation; failures fall back to `PersonalityAI`.
3. **Fog of war.** Never send foreign ground truth to the client, go through `publicWorldState()`.
4. **Types are duplicated** between `src/core/types.ts` and `ui/src/store/gameStore.ts`. Change both.
5. **Tension** must keep breathing: when adding a tension source, check `npm run sim` reports a median of 45–70 and ≤ 20% of months at 80+.
6. **One availability model.** Whether an order can be given is decided in `src/core/availability.ts` (rule layer) and mirrored for the unsent month in `ui/src/lib/availability.ts`. The order menu, the preview and Execute all use it, so a card never offers what Execute refuses.
7. **The reveal is the only post-game leak.** Foreign ground truth reaches the client only in `GET /api/reveal/:saveId` after the game is over.
8. **The codex is not state.** It never enters `WorldState`, saves or determinism.

## The playtest harness

`scripts/simulate.ts` plays whole games headlessly and prints one JSON line per policy × country:

| Policy | Plays like |
|---|---|
| `none` | never acts; crises resolve by default |
| `propaganda` | national address every month (the old dominant strategy) |
| `smart` | competent heuristic player with good crisis choices |
| `random` | random affordable orders and crisis options |
| `hawk` | mobilizes and attacks its main rival |
| `ai` | its country is run by `PersonalityAI` |
| `staff` | autopilot: Approve all + Execute (cabinet picks, the staff's meeting answers and orders from `src/core/advisors.ts`) |
| `staffswitch` | `staff`, but switches every cabinet pick that differs from the mission pick |

Key outputs: `win`, `stars`, `closeCall` (share of games with a near-loss), `winWithCloseCall`, `comebacks`, `decisionTurns`, `tensionMedian`, `tension80`, `telegraphed` (depositions preceded by a warning).

**Design targets:** smart wins 70–95% pooled (no seat below 65%; Iran's Term is exempt) · none ≤ 20% · random 15–45% · ≥ 1 decision in ≥ 50% of Term months and every Flashpoint month · every non-election deposition telegraphed. Use `--games 36` near a band edge.

### Reveal benchmarks

The reveal's ranking ladder and achievement rarity come from committed files in `data/benchmarks/`, written by `npm run bench:reveal` (`scripts/simulate.ts --benchmark 1`, which calls `scripts/benchmark.ts`). It plays every flashpoint side and every 2026 Term seat 36 times with the `smart`, `random` and `none` policies, scores each finished game with the reveal's own code, and writes one `<seat>.json` per seat (score quantiles per policy) plus `achievements.json` (the share of games that earned each seal, per mode). Narrower runs: `npm run sim -- --benchmark 1 --seats hormuz-convoy:USA,2026:TERM:USA` (does not rewrite `achievements.json`).

Each file carries a fingerprint of the code and data that decide the score (`src/infra/benchmarks.ts`: scoring, objectives, costs, chronicle, achievements, reveal, every system, and each flashpoint side's objectives and signature). When any of them changes, `tests/core/benchmarks.spec.ts` fails with "stale benchmarks": run `npm run bench:reveal` and commit `data/benchmarks/`.

## Adding content

### A crisis template (`src/core/crises.ts`)
Add an entry to `TEMPLATES`: `weight(ctx)` (0 = ineligible) and `build(ctx)` returning a headline, text and a decision with 2–3 options (`effects`, `tensionDelta`, `actions`, `backedBy`, optional `followUp`). Ground it in a real historical pattern and keep the trade-offs readable. Run `npm run sim` to check cadence.

### A flashpoint (`data/flashpoints/<id>.json`)
Follow `FlashpointSchema` in `src/core/data-loader.ts`: base `scenarioId`, `playable` sides with roles and difficulty, `setup` (wars with exhaustion, `endWars`, relations, country tweaks), per-side `objectives` (primary + bonus conditions, par, debrief) and `scripted` crises (turn 0 = cold open). Balance with `npm run sim -- --flashpoint <id> --scenario 2026 --countries A,B --policy smart,none,random`.

Each playable side can also carry a `reality` block (rows comparing the player's result with what really happened, shown in the reveal's truth table, with sources) and a `signature` achievement. Changing objectives or signatures makes the benchmarks stale.

### A codex entry (`data/codex/*.json`)
Entries explain the people, places, groups, terms and events that game text names (schema in `src/core/codex.ts`): `id`, `kind` (`person`, `place`, `group`, `term`, `event`), `name`, `aliases` (matched in game text, case-insensitive whole words by default), `obscurity` (1 widely known, 2 news followers, 3 specialist), `short` (up to 140 characters), `long` (up to 600), `valid` (`from`/`to` months: the entry is served only to games that start inside the range), optional `eras` overrides per scenario (name, short, long, obscurity, extra aliases), `related`, `map`, `sources` (required for people and events) and `asOf`. Situation briefings live in `data/codex/situations/<flashpoint id or scenario-<id>>.json` (one line, who is who, why it matters, a timeline, sources). Run `npx vitest run tests/codex` after editing. A running dev server picks up changed codex files on the next request.

### Era data (`data/scenarios/<id>.json`)
Besides leaders, overrides, relations and wars, a scenario can carry era map fields (`EraMapFieldsSchema` in `src/core/data-loader.ts`): `eraStatus` (countries that are `PART_OF` another or `NOT_INDEPENDENT` at the start, with a label, a note and an optional `until` month when they become states), `blocs` (with a side: WEST, WEST2, EAST, EAST2, NONALIGNED, OTHER), `situations` (up to 12 for the title globe, optionally linked to a flashpoint or a codex entry), `merged` (borders painted as part of a parent, such as the Soviet republics), `mapFocus`, `mapLabels` (era-only names) and `labelAllow`. The engine reads `eraStatus` and `blocs`: countries that are not states get no AI orders, pacts, world events or crisis roles, cannot be targeted as states, and cannot be led; AI pacts across the bloc line are refused. Leaders carry their real `sinceDate`. Borders that no longer exist and are not a merge go in `ui/public/era/shapes.geojson` (with from/to dates).

### A country (`data/countries/<ISO3>.json`)
Use the Natural Earth `ADM0_A3` code (the West Bank is `PSX`), validate against `CountryProfileSchema`, add it to `TIER1_COUNTRIES`, give it a leader in each scenario and a name pool in `systems/government.ts`.

## Keeping the world current (world scan)

The world moves on after release. A regular scan keeps the game's history, leaders and playable crises current, with a human approving every change:

```bash
npm run world:scan                          # read the feeds in data/world-scan/sources.json
npm run world:scan -- --input news.txt      # or a file: one headline per line, "2026-11-18 | headline | link"
npm run world:scan -- --llm anthropic       # refine with an LLM (key in .env); add --draft to draft new flashpoints
npm run world:apply -- data/world-scan/proposals/<date>.json            # apply items marked "accept": true
npm run world:apply -- <file> --ids h-JPN-...,l-JPN,b-0                  # or exactly these ids
```

1. **Scan** tags each headline with the game's countries (names, demonyms, capitals, leaders: `data/world-scan/aliases.json`) and the kind of event (war, ceasefire, coup, election, leadership change, sanctions, nuclear, unrest, disaster, blockade, cyber, terror...). It writes `data/world-scan/proposals/<date>.json` and a readable `<date>.md`:
   - **History entries** per country, skipping anything already in the profile's `keyEvents`.
   - **Leader changes** (the heuristic flags them; the LLM step or a human fills in the name).
   - **Crisis patterns**: each kind of event in the news, with the crisis cards that already cover it, and (with `--llm`) new dilemmas the game has no card for. Crisis cards are code in `src/core/crises.ts`, so these are a design backlog.
   - **Flashpoint candidates**: pairs of countries named together in conflict news, marked when a flashpoint already covers them. With `--llm --draft`, the top two uncovered ones are drafted as full flashpoint files and validated against `FlashpointSchema`.
   - **Briefing lines** for the 2026 scenario.
2. **Review**: set `"accept": true` on what you want (edit the event or impact text freely).
3. **Apply** appends history lines to `data/countries/*.json` (keeping the file layout and re-validating each profile), updates 2026 leaders and briefing lines (`b-<n>` ids), writes accepted flashpoint drafts to `data/flashpoints/` (they become playable), then starts the 2026 world and every flashpoint and plays three months as a smoke test. Run `npm test` and commit.

Run it weekly or after a major world event. The feeds must be reachable from where it runs (a cloud session needs their hosts in its network allowlist); `--input` works offline with pasted headlines.

## The development loop (devloop/)

The game is developed with a synthetic-customer loop: persona agents are interviewed, play every build through the real UI and report in a fixed format, builder personas design and build, and every decision goes into a ledger. The loop lives in `devloop/`, a self-contained module that can be copied to another repository: product-agnostic method (`method/`), a Playwright kit (`kit/`: act by visible label, a persistent driver for turn-by-turn play, page checks, feedback digest, usage ledger) and templates. World Conflict's instance (panel, team charters, goals, gate, ledger, journal, iteration runs and design specs) is in `devloop/instances/world-conflict/`. Start with [devloop/README.md](../devloop/README.md) and the current process in [devloop/HOW_WE_WORK.md](../devloop/HOW_WE_WORK.md).

`npm run playtest:smoke` runs the instance's smoke playtest (start today's flashpoint, play three months through the UI, fail on page errors or a stuck flow); `node devloop/kit/finish-flashpoint.mjs` plays a flashpoint to the end and screenshots each reveal stage. Both need `npm run dev` (or `DEVLOOP_BASE_URL`).

## Conventions

- Conventional commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`).
- Backend: Biome, 2-space, 100 columns, explicit `.js` import extensions. UI: ESLint.
- Every engine change ships with a test; every balance change ships with harness numbers in the commit message or `dev_plan/project_status.html`.
- No em dash characters anywhere; use the glossary names for player-facing words (`ui/src/lib/glossary.ts`).
- Merges resolve generated files one at a time (for `data/benchmarks/`, regenerate), never with one multi-path checkout.
